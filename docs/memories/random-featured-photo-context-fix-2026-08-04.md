# 隨機置頂照片跨流程重複修正紀錄

- 日期：2026-08-04T01:38:00+08:00
- 範圍：公開相簿的「隨機置頂照片」
- 不包含：管理員在「分類與影片」中手動指定的置頂照片
- 狀態：修正已進入 PR 驗證流程

## 使用者觀察到的問題

瀏覽婚禮流程時，某個流程（例如「進場」）抽出的兩張隨機置頂照片，在切換到「進場前」或其他流程後仍可能繼續以置頂樣式出現。問題不是固定指定的置頂照片，而是相簿層級的隨機置頂功能。

## 程式檢查結果

隨機置頂使用 `createFeaturedPhotoSelectionSession()`，每個頁面 session 會按照以下資訊保存抽樣：

- 相簿 ID
- 標籤／流程 ID
- 最少張數
- 最多張數

因此程式並不是把同一個流程的 React state 直接共用給所有流程。真正缺少的保護有兩項。

### 1. 相鄰流程之間沒有避免重複抽樣

婚禮照片可以同時屬於多個流程。原本每個流程都從自己的候選集合獨立隨機抽樣；若兩個流程的候選照片高度重疊，演算法完全可能連續抽中相同照片。從使用者角度看起來，就像上一個流程的置頂照片沒有被清除。

### 2. 快取沒有辨識候選照片集合是否已改變

原本快取 key 只包含相簿、流程與張數範圍，不包含候選照片 ID。若同一頁期間照片分類或資料集合更新，舊抽樣只會把已不存在的 ID 過濾掉，不會重新補足設定張數，可能留下過時或不足的抽樣結果。

## 修正後的契約

1. 切換到不同流程時，新的隨機抽樣會先避開上一個流程已置頂的照片。
2. 只有當新流程沒有足夠的其他候選照片時，才允許必要重複。
3. 每個流程仍保有自己的 page-session 穩定結果；切走再切回，不會因一般 re-render 或 lightbox 操作重新洗牌。
4. 候選照片 ID 集合改變時，該流程的舊快取會失效並重新抽樣，且補足目前設定允許的張數。
5. 隨機置頂仍只從目前相簿與目前流程實際可用的照片中選取。
6. 手動指定置頂照片的 `pinnedPhotoIdsByProcess`、顯示順序與管理設定完全不變。

## 維護規則

未來調整隨機置頂時，必須同時維持以下三個不變量：

1. **Context isolation**：目前流程的抽樣不能被上一流程的結果直接沿用。
2. **Candidate validity**：任何置頂 ID 都必須仍存在於目前流程的候選照片集合。
3. **Session stability**：同一流程在候選集合未變時，不應因 lightbox、語言切換或一般 re-render 重新洗牌。

若要改成每次點擊流程都重新抽樣，或要求所有流程在整個 session 中永不重複，應視為新的產品規則，不應透過修 bug 順帶改變。
